# Agent Note: 第一版的功能范围、界面和隐私底线

Status: proposed

## Problem

开发者现在用 Tavo 玩 RP，嫌它没有提示词缓存、不能调思考深度；用过 SillyTavern（ST），嫌它太复杂、界面老。Silue 先给开发者自己用，之后开源（AGPL-3.0）。第一版要先定下来做什么、不做什么，不然功能会越加越多，永远发不出去。

## Proposal

### 第一版要做

- **角色卡**：导入和编辑 V1、V2、V3 规格的卡，支持 PNG、JSON、CHARX 格式。开发者的 `万象_v2.json` 是 `chara_card_v3`，带 3 条世界书条目和 `extensions.regex_scripts`。导入已经做好，见 [角色卡导入](../../implemented/feature/2026-10-19-card-import.md)。
- **用户人设、世界书、正则**：正则用 ST 的格式（`findRegex`、`replaceString`、`placement`、`markdownOnly`、`promptOnly`……）。角色卡自带的世界书和正则、全局一份的用户人设已经做了，见 [角色卡世界书](../../implemented/feature/2026-10-19-card-lorebook.md)、[角色卡正则](../../implemented/feature/2026-10-19-card-regex.md)、[用户人设](../../implemented/feature/2026-10-19-user-persona.md)；单独的世界书文件、全局正则、多个人设还没做。
- **预设**：导入 ST 的预设（`prompts` + `prompt_order`，比如 `万象_预设.json`），可以编辑提示词条目的顺序。拼装规则见 [缓存排布](2026-10-19-prompt-cache-layout.md)。
- **聊天操作**：重新生成、左右滑动看同一条消息的多个回复、编辑、删除、从任意一条消息分支出去。数据结构见 [同步](../architecture/2026-10-19-sync-e2e-cloudflare.md)。
- **导入旧聊天**：导入 ST 的 `.jsonl` 聊天记录。Tavo 导出的就是这个格式：第一行是 `chat_metadata`、`user_name`、`character_name`、`create_date`，之后每行一条消息，字段有 `name`、`is_user`、`is_system`、`send_date`、`mes`、`original_avatar`、`extra`。开发者的 Tavo 导出文件里没有滑动出来的备选回复。`chat_metadata.variables` 也一起导入。读取文件见 [聊天记录导入](../../implemented/feature/2026-10-19-st-chat-import.md)，写进数据库见 [本地存储](../../implemented/architecture/2026-10-19-doc-store.md)，都已做好。
- **模型**：OpenAI 兼容接口，以及 Claude、Gemini、OpenAI、DeepSeek 等各家的原生接口，都要做完整。思考深度见 [思考深度](2026-10-19-thinking-depth-levels.md)。
- **其他功能**，各有单独的笔记：
  - [长期记忆](2026-10-19-long-term-memory.md)
  - [消息里的 HTML](2026-10-19-card-html-sandbox.md)
  - [后台生成](2026-10-19-background-generation.md)
  - [本机 MCP 接口](2026-10-19-local-mcp-server.md)
- **内置默认 RP 预设**：没导入任何预设也能直接开聊。

### 第一版不做

- 不做：群聊、视觉小说模式。
- 第二版再做：TTS 语音、生图、从 chub 等网站按链接导入卡、插件系统、卡片 JS 接口。
- 不在聊天里给模型发图片。
- 不做 Web 版、不做 Android（见 [技术栈](../architecture/2026-10-19-tech-stack-tauri.md)）。

### 界面

- iOS 的视觉风格，极简。
- 所有动画固定 120ms。
- 默认通栏小说排版，可以切换成气泡。
- 跟随系统深浅色。
- 字体、字号、行距可以调。
- 支持用户自定义 CSS 主题。
- 中英双语：所有界面文字从第一天起放进翻译文件，代码里不写死任何一句中文或英文。

### 隐私

- 不收集任何使用数据，不自动上报崩溃。
- 出错时日志存在本地，设置里有「导出日志」按钮，导出时自动去掉 API Key 和聊天内容。
- API Key 存在系统的安全存储里（Windows 凭据管理器 / iOS 钥匙串），不明文存进 SQLite。
- 所有数据可以导出成一个备份文件，也能从备份文件恢复。

## Alternatives considered

- **兼容 ST 的扩展插件** — 最强的理由：能直接用 ST 社区现成的大量插件。否掉的原因：ST 的扩展依赖它内部的代码结构，要兼容就得照着 ST 的架构写，等于重写一个 ST，而太复杂正是开发者离开 ST 的原因。
- **不兼容 ST 的格式，自己定一套** — 最强的理由：格式设计可以不受历史包袱影响。否掉的原因：社区里的卡、世界书、预设都是 ST 格式，不兼容的话，新用户手上的资源都用不了。
- **默认气泡排版** — 最强的理由：大多数聊天 App 都长这样，用户最熟悉。否掉的原因：RP 的回复动不动几百上千字，气泡会把两边都挤窄；改成可以切换。
- **第一版就做群聊** — 最强的理由：社区里有不少多角色玩法。否掉的原因：开发者明确不要。

## Acceptance criteria

- 开发者能导入 `万象_v2.json`、`万象_预设.json`、`万象-正则.zip`、`Tavo_万象_1HNyS.jsonl`，在 Silue 里接着这段聊天往下玩，并且开发者确认体验不比 Tavo 差。
- 代码里搜不到写死的界面文字（用一条 lint 规则检查）。
- 导出的日志文件里搜不到 API Key，也搜不到任何一条消息的原文。

## Risks

- **范围还是偏大**：长期记忆、同步、后台代跑、HTML 沙盒都不简单。如果进度太慢，先砍掉 iOS 后台下载和 MCP 接口。
- **CHARX 格式**：读取已经按 V3 规格实现，导出还没做。
