# Agent Note: 用标准答案测试锁死发给模型的请求内容

Status: proposed

## Problem

缓存只认「从开头算起完全一样」的提示词，差一个字、一个空格、一个字段的顺序，缓存就失效（见 [缓存排布](../feature/2026-10-19-prompt-cache-layout.md)）。开发者不看代码，AI 改代码时很可能在不知不觉中改动了请求内容：缓存悄悄失效，花费上去了，也没人发现。

另外，开发者没有 Mac，iOS 上的问题只能在真机上查，越晚发现越难修。

## Proposal

- **标准答案测试**：
  - 给定一张卡、一套预设、一段聊天、一组设置，把最终发给每家模型的 HTTP 请求（URL、请求头里和内容有关的字段、请求体）逐字存成文件，放在 `core` 的测试数据里。
  - 测试时重新拼一遍，和文件逐字比较，不一样就失败。
  - 有意修改请求内容时，要用一条命令更新标准答案，并在提交里写明为什么改。
- **缓存前缀测试**：同一段聊天连续拼两轮，检查第二轮的请求里，除了新加的那几条消息，前面的部分和第一轮逐字相同。
- **测试数据**：用开发者的万象卡、万象预设、万象正则，以及 Tavo 导出的那段 203 条消息的聊天。这些数据里有成人内容，放进公开仓库之前要问开发者，否则改用自己写的测试卡。
- **单元测试**：`core` 里的所有逻辑（卡片解析、正则、世界书触发、记忆、同步冲突、加密）用 Vitest。
- **界面测试**：在电脑的浏览器里用 Playwright 自动跑。
- **iOS 真机清单**：键盘、切到后台、划掉 App、HTML 卡、滚动性能这些，写成一张清单，每次发版前手动过一遍。

### 已经落地的部分

OpenAI 兼容请求和角色卡提示词的标准答案、缓存前缀测试已经有了，见 [OpenAI 兼容接口](../../implemented/feature/2026-10-19-openai-compatible-chat.md)。更新命令是 `npm test -- -u`。

## Alternatives considered

- **只写普通单元测试，不存整份请求** — 最强的理由：测试文件小，改代码时不用每次都更新一堆标准答案。否掉的原因：普通断言只检查几个字段，查不出空格、字段顺序这类会让缓存失效的变化，而缓存是这个项目的首要目标。
- **在 iOS 上也自动跑界面测试** — 最强的理由：iOS 的问题能被自动发现。否掉的原因：没有 Mac 就跑不了 iOS 模拟器，真机自动化的成本太高；第一版用手动清单代替。

## Acceptance criteria

- 故意在拼提示词的代码里多加一个空格，标准答案测试会失败。
- `npm test` 一条命令跑完 `core` 的全部测试，GitHub Actions 每次提交都会跑（见 [CI 与发布](../process/2026-10-19-ci-and-release.md)）。
- iOS 真机清单放进仓库，发版流程里写明要过一遍。

## Risks

- **标准答案被随手更新**：AI 可能为了让测试通过，直接更新标准答案。更新标准答案的提交必须单独写明原因，代码审查时要看。
- **测试数据里有私人内容**：开发者的卡和聊天记录不能未经同意放进公开仓库。
