# Agent Note: 界面按 iOS 风格重做：侧栏逐级进入、设置改成弹出面板、消息区倒序滚动贴底

Status: implemented

## Problem

之前的界面是功能堆出来的：侧栏从上到下依次是接口配置表单、用户人设表单、预设面板、角色列表、聊天列表，全挤在一列里；按钮是浏览器默认样式；消息下面的「重新生成 / 编辑 / 删除」是文字按钮，每条都显示。开发者看到后的原话是「UI太他妈恶心了吧 你都忘记了要弄UIUX」。

[第一版范围](../../proposed/feature/2026-10-19-v1-scope.md) 里定过界面要求：iOS 视觉风格、极简、动画 120ms、默认通栏小说排版、跟随系统深浅色、所有文字放进翻译文件。

## Decision

- 代码在 `packages/app/src`：`App.tsx`（侧栏和聊天）、`SettingsSheet.tsx`（设置面板）、`icons.tsx`（图标）、`App.css`。
- 颜色、间距照 iOS 系统色：浅色背景 `#ffffff`、强调色 `#007aff`；深色背景 `#000000`、强调色 `#0a84ff`；次要文字用 `rgba(60,60,67,0.6)` / `rgba(235,235,245,0.6)`。都写成 `:root` 上的 CSS 变量，`prefers-color-scheme: dark` 时换一套。动画统一用 `--speed: 120ms`。
- 侧栏逐级进入（iOS 的导航方式）：第一层是角色列表（大标题「角色」，右上角设置和导入），点角色进第二层聊天列表（返回、导入聊天、新建聊天）。角色没有头像图时用名字首字做圆形头像，颜色按名字算。
- 设置改成弹出面板：顶部分段控件切「模型 / 人设 / 预设」，内容是 iOS 分组列表（左边标签、右边输入框）。按 Esc、点背景、点「完成」都能关。没配接口时自动弹出「模型」页。
- 宽度 ≤ 720px（手机）时只显示一栏：选了聊天显示聊天，左上角返回；设置面板改成从底部弹出。
- 聊天区：
  - 正文一栏居中，最宽 760px，字号 16px、行距 1.8（变量 `--reading-size`、`--reading-leading`，以后做字体设置时改这两个）。
  - 用户消息是圆角浅灰块，AI 消息不加底色，消息之间用细线分开（通栏小说排版）。
  - 操作按钮换成图标：最后一条放在正文下面（长回复不用滚回顶部找重新生成），其余放在名字那一行的右边；鼠标移上去才显示，触屏设备一直显示。
  - 输入框是圆角胶囊，按 Enter 发送，Shift+Enter 换行，输入法选字时按 Enter 不发送；发送按钮在生成时变成停止。
- 滚动贴底：消息区用 `flex-direction: column-reverse`，滚动原点在底部（`scrollTop` 0 就是最底下）。打开聊天就在最底部，生成时内容变高、iframe 量出高度时浏览器自己保持贴底，往上翻了就停在原处。换聊天、发送时 `scrollTo({ top: 0 })`。没有用 JS 判断「在不在底部」。

## Alternatives considered

- **用 JS 跟着滚：ResizeObserver 发现内容变高就设 `scrollTop = scrollHeight`，`onScroll` 判断离底部近不近** — 最强的理由：直观，所有浏览器行为一致，滚动方向是正常的。否掉的原因：真 App 里打开 203 条消息的聊天，停在 35940 / 39908，没到底。推测原因：iframe 量出高度时浏览器自己也会发 scroll 事件，`onScroll` 看到离底部很远就把「贴底」关了（没有逐帧确认）；改成「只有往上滚才算离开」后，打开同一段聊天仍然有一次停在中间。`column-reverse` 不需要判断，在 203 条和 10 条两段聊天之间来回切换 4 次，每次都在最底部。
- **操作按钮一直放在消息下面（占一行）** — 最强的理由：位置固定，好找。否掉的原因：按钮平时隐藏，空着的一行在每条消息下面都留了 30px 空白，用户消息的圆角块里尤其明显。
- **设置做成单独页面（侧栏第三层）** — 最强的理由：手机上更像 iOS 的「设置」App。否掉的原因：设置要在聊天时随时改（换模型、换预设），弹出面板不用离开当前聊天。
- **iframe 里的文字颜色继续从外层复制** — 最强的理由：卡片 HTML 的文字颜色和外面的消息完全一致。否掉的原因：只在 iframe 加载时复制一次，切换深浅色后已经建好的 iframe 还是旧颜色（浅色模式下白字白底）。外层 `--label` 是纯黑 / 纯白，和 iframe 里 `color-scheme: light dark` 的默认文字色一样，不复制也一致。

## Consequences

- 2026-10-20 在真 App 里验证（开发模式，Windows WebView2，用调试端口截图）：
  - 角色列表、聊天列表、聊天区、设置面板三个页面在深色和浅色下都截过图。
  - 203 条和 10 条的两段聊天来回切换 4 次，每次都停在最底部（`scrollTop` 0）；往上滚 3000px 后停在原处。
  - 切换深浅色后，卡片 HTML 里的正文颜色跟着变。
  - 390×844 宽度下只显示一栏，设置面板从底部弹出。
- 还没做（`v1-scope` 里定过的）：
  - 切换成气泡排版。
  - 字体、字号、行距设置（变量已经留好）。
  - 自定义 CSS 主题。
- 已知问题：
  - 万象卡的状态栏把文字颜色写死成 `#e8e0f0`（按深色背景写的），浅色模式下看不清；卡片自己的写法，没处理。
  - 模型输出里的 `<writing_plan>` 这类带下划线的标签不是合法 HTML 标签名，会原样显示成文字。
  - `column-reverse` 滚动依赖浏览器正确处理倒序滚动（`scrollTop` 往上是负数），Windows 的 WebView2 实测正常；iOS 的 WKWebView 还没验证。
