# Agent Note: 导入 SillyTavern 预设，按预设顺序拼提示词，带深度的条目挪到聊天记录之后

Status: implemented

## Problem

开发者在 Tavo 里用的是自己写的 `万象_预设.json`（SillyTavern 聊天补全预设）：Main Prompt 是 319 字的写作要求，Post-History Instructions 是 196 字的「写之前自检」，`enhanceDefinitions`、`nsfw` 关着，其余是标准的标记条目（世界书、人设、角色描述……聊天记录）。Silue 之前只有内置顺序和 ST 默认的英文 Main Prompt，这两段从来没发给过模型。之前把这个文件当角色卡导入，还会变成一张叫「万象预设」的空卡（已在 [角色卡导入](2026-10-19-card-import.md) 里修掉）。

[第一版范围](../../proposed/feature/2026-10-19-v1-scope.md) 要求导入 ST 预设；[缓存排布](../../proposed/feature/2026-10-19-prompt-cache-layout.md) 要求把带深度的注入挪到最后。

## Decision

- 代码在 `packages/core/src/prompt/preset.ts`。`buildChatPrompt` 多了 `preset` 参数：传了就按预设拼，不传还是原来的内置顺序（已有的标准答案不变）。
- 拼装规则照 SillyTavern，2026-10-19 对照过 release 分支的 `public/scripts/openai.js`、`PromptManager.js`：
  - 顺序取 `prompt_order` 里 `character_id` 为 100001 的那份（ST 全局顺序存在这个 id 下），没有就用第一份，再没有就按 `prompts` 的顺序全部启用。
  - 关掉的条目跳过，`main` 关不掉（ST 的 `source !== 'main'`）。
  - 标记条目填内容：`worldInfoBefore` / `worldInfoAfter` 用常驻世界书，按 `wi_format` 的 `{0}` 套格式；`personaDescription` 用 [用户人设](2026-10-19-user-persona.md)；`charPersonality`、`scenario` 按 `personality_format`、`scenario_format` 套格式；`dialogueExamples` 每段 `<START>` 前加 `new_example_chat_prompt`。
  - `chatHistory` 前面加一条 `new_chat_prompt`（默认 `[Start a new Chat]`）。
  - 卡片的 `system_prompt` 覆盖 `main`、`post_history_instructions` 覆盖 `jailbreak`，`{{original}}` 是预设原文；条目设了 `forbid_overrides` 就不覆盖。
- 和 ST 不同的地方：
  - `injection_position: 1`（插在聊天记录的某个深度）的条目一律挪到聊天记录之后：先放本轮触发的世界书，再放这些条目（深度大的在前，同深度按 `injection_order`），最后是聊天记录之后的普通条目（一般是 `jailbreak`）。预设原文不改，原位置还在条目上；设置面板里列出被挪动的条目名。
  - 相邻的 system 消息合成一条（ST 默认每条单独发）。聊天记录里的消息不合并。
- 存储：`presets` 集合，每份存名字和导入的原文（保留不认识的字段）；当前用哪份存在 `settings/app` 的 `activePresetId`，空字符串表示不用预设。名字取预设里的 `name`，没有就用文件名。
- 采样参数（2026-10-20 加）：取预设里的 `temperature`、`top_p`、`frequency_penalty`、`presence_penalty`、`openai_max_tokens`，接在请求体最后，没写的、不是数字的不发；`top_k`、`min_p` 这类不在 OpenAI 规格里的不发。最大长度发 `max_tokens`，接口地址是 `api.openai.com` 时发 `max_completion_tokens`（OpenAI 官方的推理模型不认 `max_tokens`，https://platform.openai.com/docs/api-reference/chat/create ）。没选预设时什么都不发，请求体和以前一样。
- 界面：侧栏「提示词预设」：下拉框选预设或「不用预设」，导入按钮；导入后自动选中。导入的不是预设时提示「这不是 SillyTavern 的聊天补全预设（缺少 prompts）」。面板里显示实际发送的采样参数；可以删除当前预设（点两次确认），删除后回到「不用预设」。

## Alternatives considered

- **照 ST 把带深度的条目插进聊天记录中间** — 最强的理由：和预设作者在 ST 里调出来的效果一样。否掉的原因：插入点每轮都在变，从那里往后缓存全部失效；缓存排布笔记里开发者已经同意先挪到最后。开发者的万象预设没有带深度的条目，这次不影响他。
- **没选预设时也走预设拼装（内置一份 ST 默认预设）** — 最强的理由：只有一套拼装代码。否掉的原因：内置顺序的格式（`{{char}}'s personality:`、`Example dialogue:`）和 ST 默认预设不一样，换过去会改掉已有的三份标准答案和已经实测过的缓存行为；等做预设编辑界面时再统一。
- **每个条目单独发一条 system 消息（ST 默认）** — 最强的理由：和 ST 一模一样。否掉的原因：有的接口只认第一条 system 消息或者会把多条拼在一起，合成一条行为更可预测；内置顺序本来也是合成一条。

## Consequences

- 2026-10-19 在真 App 里验证（开发模式，万象卡和聊天只在本地，不进仓库）：
  - 导入 `万象_预设.json` 后自动选中；把角色卡当预设导入，显示上面的报错。
  - 同一段聊天，系统提示从 6828 字变成 7066 字，开头换成预设的 Main Prompt；聊天记录之后那条从 1039 字变成 1223 字（世界书的万象提醒 + 预设的写之前自检）。
  - 用官方 DeepSeek 真发一条「原样抄出你收到的『写之前自检』第 1 条」，模型抄出了预设里的第 1 条。
  - 验证完预设保持选中（开发者在 Tavo 里一直用它）。
  - 2026-10-20：面板显示「发给接口的采样参数：temperature: 1, max_tokens: 8192」；带着这两个参数用官方 DeepSeek 发一条，正常返回，输入 6551 个 token 里缓存命中 5120 个。再导入一份同样的预设然后删掉，列表里只剩原来那份。
- 测试：`preset.test.ts` 7 个，覆盖顺序和挪动、标准答案（`__golden__/preset-card.json`）、关掉的条目、卡片覆盖和 `forbid_overrides`、列出被挪动的条目、两轮之间前缀不变、报错、存储。
- 还没做（代码里有 `shortcut:` 注释）：
  - 续写、代写（`continue_nudge_prompt`、`impersonation_prompt`），以及 `{{random}}`、`{{getvar}}` 这类宏。
  - 编辑条目顺序、把单个条目改回原位置。
  - 模型不支持某个采样参数时（比如 OpenAI 的推理模型不认 `temperature`），接口会报错，只能换「不用预设」；还没有按模型过滤参数。
  - 示例对话没有拆成 `example_user` / `example_assistant` 消息。
